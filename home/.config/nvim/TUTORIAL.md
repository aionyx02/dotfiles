# Neovim 入門 — 這台機器的版本

這份設定的定位是**終端內的隨手編輯器**：改設定檔、寫 git commit、從 yazi 開檔。
大型專案仍然走 JetBrains / Sublime，不必勉強自己在 nvim 裡做完所有事。

設定原則只有一條：**vim 的原生鍵位一個都不覆蓋**。所以你在任何教學、任何機器、
任何同事的 vim 上學到的東西，在這裡 100% 適用；反過來，你在這裡練出來的手感
到別台機器上也不會失效。自訂的東西只有 5 個鍵，全部掛在 `\` 底下。

---

## 0. 最重要的一課：怎麼離開

沒有這一段，第一天就會卡死在畫面裡。

| 情況 | 打什麼 |
|---|---|
| 存檔並離開 | `:wq` 然後 Enter |
| 不存檔，直接離開 | `:q!` 然後 Enter |
| 只存檔，不離開 | `:w` 然後 Enter |
| **完全不知道現在在哪個狀態** | 按 `Esc`，多按幾次也沒關係 |

`Esc` 是回到「什麼都沒發生」的原點。任何時候按下去都是安全的。
打指令前先按一次 `Esc`，是所有 vim 使用者的肌肉記憶。

> **★ 為什麼要打冒號**
> `:` 會把游標跳到最底下那一行，那是 vim 的「指令列」——它才是 vim 真正的介面，
> 選單和快捷鍵都只是它的捷徑。以後看到教學寫 `:something`，意思就是
> 「按 Esc、按冒號、打 something、按 Enter」。

## 1. 模態是什麼

一般編輯器裡，鍵盤永遠在打字。vim 不是——vim 的鍵盤**大部分時間是遙控器**，
只有你明確說「我要打字」時才變成鍵盤。

| 模式 | 進入方式 | 這時候按鍵是什麼意思 |
|---|---|---|
| **Normal**（預設） | `Esc` | 遙控器：`d` 是刪除、`y` 是複製、`j` 是往下 |
| **Insert** | `i` `a` `o` … | 鍵盤：打什麼就進去什麼 |
| **Visual** | `v` `V` `Ctrl+Q` | 選取範圍，選完再下指令 |
| **Command** | `:` | 打指令 |

畫面左下角會顯示現在在哪個模式。**看不出來就按 `Esc`**。

> **★ 這件事最反直覺，但它就是 vim 的全部價值**
> 因為 Normal 模式下每個字母都是一個指令，所以「刪除三行」是 `3dd`、
> 「刪到這個括號結束」是 `di)`、「把這個字換掉」是 `ciw`。
> 這些組合在一般編輯器裡要靠滑鼠拖曳或一堆快捷鍵，在這裡是兩三個字母。
> 前三天你會覺得處處不順，那是正常的——你在拆掉一套用了二十年的習慣。

## 2. 移動（Normal 模式）

方向鍵可以用，不必為了純粹而折磨自己。但 `hjkl` 值得練，因為右手不用離開基準位置。

```
        k  ↑
   h ←        → l
        j  ↓
```

| 鍵 | 動作 |
|---|---|
| `h` `j` `k` `l` | 左 下 上 右 |
| `w` / `b` | 下一個詞頭 / 上一個詞頭 |
| `0` / `^` / `$` | 行首 / 行首第一個非空白 / 行尾 |
| `gg` / `G` | 檔案開頭 / 檔案結尾 |
| `{` / `}` | 上一個 / 下一個空行（等於一段一段跳） |
| `Ctrl+D` / `Ctrl+U` | 往下 / 往上半頁 |
| `20G` 或 `:20` | 跳到第 20 行 |
| `f` + 字元 | 跳到這一行的下一個該字元（`f=` 就是跳到下一個等號） |
| `%` | 在成對的括號之間跳 |

> **★ 左邊的行號是相對的**
> 游標所在那行顯示的是絕對行號，其他行顯示的是「離你幾行」。
> 所以要跳到上面第 7 行，看一眼就知道打 `7k`，不用自己數。
> 這個設計就是為了讓「數字 + 動作」變成直覺——那是 vim 最核心的加速器。
>
> 所以畫面上會是「往上 3 2 1、游標那行是真實行號、往下 1 2 3」。這不是錯亂，
> 是刻意的。要臨時關掉比較看看，打 `:set rnu!`（再打一次切回來，不影響設定檔）；
> 確定不要了就把 `lua/options.lua` 裡的 `o.relativenumber = true` 刪掉。

## 3. 編輯

### 進入 Insert 模式

| 鍵 | 從哪裡開始打字 |
|---|---|
| `i` | 游標**前**（insert） |
| `a` | 游標**後**（append） |
| `I` | 這一行的開頭 |
| `A` | 這一行的**結尾** ← 最常用 |
| `o` | 在下面開一行新的 |
| `O` | 在上面開一行新的 |

打完字按 `Esc` 回 Normal。

### 刪除與修改（Normal 模式）

| 鍵 | 動作 |
|---|---|
| `x` | 刪一個字元 |
| `dd` | 刪一整行 |
| `3dd` | 刪三行 |
| `dw` | 刪一個詞 |
| `D` | 從游標刪到行尾 |
| `cw` | 刪一個詞**並進入 Insert**（change word） |
| `ciw` | 不管游標在詞的哪個位置，整個詞換掉 ← 非常常用 |
| `ci"` | 把引號**裡面**的東西換掉 |
| `u` | 復原 |
| `Ctrl+R` | 重做 |
| `.` | **重複上一個動作** ← vim 最強的一個鍵 |

> **★ 動作 + 範圍 是一套文法**
> `d` = 刪除，`w` = 一個詞，所以 `dw` = 刪一個詞。
> 同一套範圍換給 `c`（修改）、`y`（複製）都成立：`yw` 複製一個詞、`y$` 複製到行尾。
> 你不是在背幾十個快捷鍵，你在學一個很小的文法。

### 複製貼上（vim 內部）

| 鍵 | 動作 |
|---|---|
| `yy` | 複製一行 |
| `yw` | 複製一個詞 |
| `p` | 貼在游標**後** |
| `P` | 貼在游標**前** |

複製成功時被複製的範圍會閃一下——那是這份設定加的，因為 vim 原生對 `y` 沒有任何回饋。

## 4. 跟系統剪貼簿之間

vim 的 `y` 進的是 vim 自己的暫存器，**不會**進 Windows 剪貼簿。這是刻意保留的原生行為：
否則你隨手按個 `dd` 刪一行，剛剛從瀏覽器複製的東西就沒了。

| 要做的事 | 打什麼 |
|---|---|
| 複製到 Windows 剪貼簿 | `"+y`（先選取，或用 `"+yy` 複製整行） |
| 從 Windows 剪貼簿貼上 | `"+p`，或直接按 **`Ctrl+V`** |

> **★ `Ctrl+V` 貼上是安全的**
> nvim 支援 bracketed paste：即使你人在 Normal 模式，終端貼進來的文字也會被
> 當成「貼上」，不會被當成一連串指令執行。這個坑 nvim 已經幫你處理掉了。
>
> **★ 但也因此 `Ctrl+V` 不能拿來進視覺區塊模式**
> WezTerm 把 `Ctrl+V` 攔下來當貼上了，根本傳不到 nvim。
> vim 原生就準備了替代鍵：**`Ctrl+Q`**，功能跟 `Ctrl+V` 完全相同。
> 它存在的理由就是「`Ctrl+V` 常常被系統搶走」。

## 5. 選取（Visual 模式）

| 鍵 | 選取方式 |
|---|---|
| `v` | 逐字元選 |
| `V` | 整行選 |
| `Ctrl+Q` | **整欄選**（區塊）—— 改一整排的縮排、在每行行首加字元 |
| `gv` | 重新選回上次選的範圍 |

選好之後可以接 `d` 刪除、`y` 複製、`"+y` 複製到系統剪貼簿、`>` 或 `<` 調整縮排。

區塊模式的經典用法：`Ctrl+Q` 選好一整欄 → 按 `I` → 打要插入的字 → 按 `Esc`，
那些字會出現在**每一行**。

## 6. 搜尋與取代

| 鍵 / 指令 | 動作 |
|---|---|
| `/文字` | 往下搜尋 |
| `?文字` | 往上搜尋 |
| `n` / `N` | 下一個 / 上一個結果 |
| `*` | 搜尋游標所在的那個詞 |
| `:%s/舊/新/g` | 全檔取代 |
| `:%s/舊/新/gc` | 全檔取代，但每一處都問你 y/n |
| `:noh` | 把搜尋高亮關掉 |

搜尋全小寫時不分大小寫；只要你打了任何一個大寫字母，就自動變成精確比對。

跨檔案搜尋用 `:grep 要找的東西`（已經接到 ripgrep），結果進 quickfix 清單：
`:copen` 打開清單、`:cnext` / `:cprev` 在結果之間跳。
不過日常用 `\g`（下一節）會更順手。

## 7. 這份設定加的 5 個鍵

全部以 `\`（反斜線，vim 規範中保留給使用者的前綴鍵）開頭。
「按 `\` 再按 `f`」寫成 `\f`。

| 鍵 | 功能 |
|---|---|
| `\f` | **找檔案**（模糊搜尋檔名） |
| `\g` | **全文搜尋**（ripgrep，邊打邊找） |
| `\b` | 切換已經開著的檔案 |
| `\y` | 開 **yazi**，游標停在當前檔案上 |
| `\Y` | 開 **yazi**，開在當前工作目錄 |

另外 git 追蹤中的檔案會多兩個鍵（借用 vim 原生 diff 模式的跳轉鍵，非 diff 模式下它們本來就沒作用）：

| 鍵 | 功能 |
|---|---|
| `]c` | 跳到下一處 git 改動 |
| `[c` | 跳到上一處 git 改動 |

左邊那一欄的 `+` `~` `_` 就是 gitsigns 標的新增 / 修改 / 刪除。

### 在 `\f` `\g` `\b` 的清單裡

| 鍵 | 動作 |
|---|---|
| 直接打字 | 過濾 |
| `Ctrl+J` / `Ctrl+K` 或方向鍵 | 上下移動 |
| `Enter` | 開啟 |
| `Ctrl+S` | 開在水平分割 |
| `Ctrl+T` | 開在新分頁 |
| `Esc` | 取消 |

> **★ 官方文件寫的 `Ctrl+V`（開在垂直分割）在這裡按不出來** —— 被 WezTerm 攔去貼上了。
> 需要垂直分割就先 `Enter` 開起來，再用 `Ctrl+W v`。

### 在 `\y` 叫出來的 yazi 裡

那就是**你平常在用的那個 yazi**，同一份設定、同一組鍵位——`F2` 改名、`F3` 找這層、
`F4` Everything 全機搜尋、`` ` `` 開頭的那些自訂鍵，全部照舊。
選好檔案按 `Enter` 就在 nvim 裡開起來，按 `q` 則是取消回到 nvim。

yazi.nvim 另外在那個視窗裡加了幾個鍵：

| 鍵 | 動作 |
|---|---|
| `F1` | 顯示這一組說明 |
| `Ctrl+X` | 開在水平分割 |
| `Ctrl+T` | 開在新分頁 |
| `Ctrl+S` | 在 yazi 當下的目錄做全文搜尋（會轉給 fzf-lua） |
| `Ctrl+Q` | 把選取的檔案送進 quickfix 清單 |
| `Ctrl+O` | 開啟並自己挑要開在哪個視窗 |

> **★ 官方預設的 `Ctrl+V`（開在垂直分割）在這裡同樣按不出來**——被 WezTerm 攔去貼上了。
> 用 `Ctrl+X` 開水平分割，或先 `Enter` 開起來再 `Ctrl+W v`。
>
> **★ 預設的 `Ctrl+Y`（複製相對路徑）已經在設定裡關掉**——那個功能需要 `realpath`，
> Windows 上沒有。留著只會讓 `:checkhealth` 永遠掛一個修不好的警告。

## 8. 多檔案：buffer / 分割視窗 / 分頁

vim 的「已開啟檔案」叫 **buffer**，跟「視窗」是兩件事：一個 buffer 可以同時顯示在多個視窗裡。

| 鍵 / 指令 | 動作 |
|---|---|
| `\b` | 列出所有 buffer 並切換 |
| `:bd` | 關掉當前 buffer |
| `Ctrl+W v` | 垂直分割（左右） |
| `Ctrl+W s` | 水平分割（上下） |
| `Ctrl+W h/j/k/l` | 在分割視窗之間移動 |
| `Ctrl+W q` | 關掉當前分割 |
| `Ctrl+W o` | 只留當前這個，其他都關掉 |

> **★ `Ctrl+W` 是 vim 的視窗前綴鍵，所以這份設定不會去動它。**
> 注意跟 WezTerm 的分屏區分：`Alt+HJKL` 切的是 **WezTerm 的分屏**，
> `Ctrl+W h/j/k/l` 切的是 **nvim 內部的分割**。兩層是獨立的，不會互相干擾。

## 9. 跟你這台終端的交互（會踩到的都在這）

| 現象 | 原因與對策 |
|---|---|
| `Ctrl+V` 進不了區塊模式 | WezTerm 攔去當貼上了。**用 `Ctrl+Q`**，功能相同 |
| 拖曳選取變成 nvim 的 visual，沒有自動複製 | nvim 接管了滑鼠。**按住 `Shift` 拖曳**就會繞過 nvim，回到 WezTerm 的「選取即複製」 |
| `Ctrl+Tab`、`Ctrl+1~9`、`Alt+[` `]`、`Alt+HJKL` 在 nvim 裡沒反應 | 這些都是 WezTerm 的分頁 / 分屏鍵，永遠傳不到 nvim。nvim 預設也沒用到它們，所以沒有損失 |
| `Ctrl+C` | 沒選取文字時會正常傳給 nvim（等於中止 / 近似 `Esc`）；有選取時 WezTerm 會拿去複製 |
| `Ctrl+S` 按了沒反應 | 這份設定沒綁它（原生 vim 也沒有）。存檔是 `:w`。不會當機——WezTerm 沒開 XOFF 流量控制 |
| 從 yazi 按 `Enter` 開檔還是跳 Sublime | 這是刻意保留的。要用 nvim 開就按 **`O`**（大寫）從選單挑 `nvim` |
| 新建的 `.ps1` 中文變亂碼 | 不會發生。這份設定會自動幫新建的 `.ps1` 加上 UTF-8 BOM |

## 10. 編譯與跳到錯誤行

這一節只講機制，不綁語言——把機制看懂之後，任何語言都是換一條指令的事。

### 分工：nvim 負責定位，終端負責執行

| 誰 | 負責 |
|---|---|
| **nvim** | 編譯 → 解析編譯器的錯誤訊息 → **游標直接跳到出錯的檔案與行** |
| **WezTerm 分屏** | 執行程式、看輸出、餵輸入 |

> **★ 為什麼不在 nvim 裡跑程式**
> 你已經有更好的終端了：`Alt+Shift+-` 開下方分屏、`Alt+J` / `Alt+K` 來回切，
> 那裡有你的 starship、有 scrollback、關掉也不影響編輯器。
> nvim 唯一能做、而終端做不到的事，是**把錯誤訊息變成可以跳的位置**——
> 這一節講的就是那件事。

### 檔名替換：`%` 是什麼

在指令列裡，`%` 會被展開成當前檔案的路徑，後面可以接修飾詞：

| 寫法 | 展開成 |
|---|---|
| `%` | 當前檔案（相對路徑） |
| `%:r` | 去掉副檔名（**r**oot） |
| `%:e` | 只有副檔名（**e**xtension） |
| `%:t` | 只有檔名，不含目錄（**t**ail） |
| `%:h` | 只有目錄（**h**ead） |
| `%:p` | 絕對路徑 |
| `%:S` | 跳脫成 shell 安全的字串（路徑有空白時必備） |

修飾詞可以疊：`%:p:h` = 當前檔案所在目錄的絕對路徑。完整清單見 `:help filename-modifiers`。

> **★ Windows 注意**：MinGW 的 g++ 在 `-o` 給的名稱沒有副檔名時會**自動產生 `.exe`**
> （實測確認），所以 `%:r` 可以直接當執行檔名用。

### 最快的一次性：`:!`

```vim
:!<指令> %
```

輸出直接印在畫面下方，按 Enter 回編輯器。

> **★ 三個限制，決定了它只適合「跑一下看看」**
> 1. 它是**同步**的：程式沒結束，nvim 就一直卡著
> 2. **不能互動**：需要你打字餵 stdin 的程式，用這個會很痛苦——那種請開 WezTerm 分屏
> 3. 錯誤訊息只是**一坨文字**，不能跳

### `:make`：把錯誤訊息變成可以跳的清單

`:make` 執行的是 `'makeprg'` 這個選項的內容，預設值就是 `make`。改掉它：

```vim
:setlocal makeprg=<編譯指令>\ %
```

> **★ 空白一定要用反斜線跳脫。** 選項值是以空白分隔的，不跳脫的話 nvim 只會吃到第一個字。
> 這是設 `makeprg` 唯一會讓人卡住的地方。
>
> **★ 用 `setlocal` 而不是 `set`**：只影響當前這個 buffer，不會汙染你同時開著的其他檔案。

`:make` 跑完之後，輸出會被 `'errorformat'` 解析成一個**清單**——每一項都記著檔案、行號、欄號與訊息。有錯誤時游標會直接跳到第一個。

### `:compiler`：不用自己寫解析規則

`'errorformat'` 是一串描述「編譯器的錯誤訊息長什麼樣」的樣板，自己寫很痛苦。nvim 內建了 **150 多份**現成的：

```vim
:compiler <名稱>
```

打 `:compiler ` 之後按 `Tab` 可以補全看到全部清單（gcc、cargo、rustc、javac、powershell、pytest、mypy、eslint、zig…）。

但它們設的東西**不一樣**，這點必須知道：

| `:compiler` | 設 `errorformat` | 設 `makeprg` |
|---|---|---|
| `gcc` | ✅ | ❌ 維持 `make`，要自己補 |
| `rustc` / `cargo` / `javac` / `powershell` | ✅ | ✅ 直接可用 |

所以碰到只給 errorformat 的，標準組合是「`:compiler` 負責解析、`:setlocal makeprg=` 負責編譯」。

> **★ 作用域**：`:compiler` 只作用在**當前 buffer**，`:compiler!`（加驚嘆號）才是全域。
> `:help :compiler` 有明確寫。

### quickfix：在錯誤之間跳

`:make` 產生的那個清單叫 **quickfix**：

| 指令 | 動作 |
|---|---|
| `:copen` / `:cclose` | 開啟 / 關閉清單視窗 |
| `:cnext`（`:cn`） | 下一個錯誤 |
| `:cprev`（`:cp`） | 上一個錯誤 |
| `:cfirst` / `:clast` | 第一個 / 最後一個 |
| `:cc 3` | 跳到第 3 項 |
| 在清單視窗裡按 `Enter` | 跳到游標所在那一項 |

> **★ 原生沒有單鍵。** 你在網路上會看到 `]q` / `[q`——那是 **`vim-unimpaired` 外掛**的鍵位，
> 你沒裝那個外掛，按了不會有任何反應。不要以為是設定壞了。
> 真的常用到覺得煩再說，那時候綁一個 `<leader>` 鍵就好。

### 完整流程長這樣

```vim
:compiler <編譯器名>              " 備好錯誤訊息的解析規則
:setlocal makeprg=<編譯指令>\ %   " 告訴 :make 執行什麼（空白要跳脫）
:make                             " 編譯。有錯就停在第一個錯誤
:copen                            " 看完整清單（可選）
:cnext                            " 下一個錯誤
```

編譯過了之後——**執行與看輸出開 WezTerm 分屏**，不要在 nvim 裡做。

### 五個會卡住的地方

1. **`:make` 說找不到 make**：`'makeprg'` 還是預設的 `make`，而當前目錄沒有 Makefile。設 `makeprg` 或先 `:compiler`
2. **`makeprg` 只吃到第一個字**：空白沒有用 `\` 跳脫
3. **`:!` 之後 nvim 沒反應**：那支程式還在跑，或它在等你輸入。`Ctrl+C` 中斷，改用 WezTerm 分屏
4. **`:cnext` 說沒有錯誤清單**：`:make` 沒跑過，或這次編譯全部成功
5. **想在 `:!` 裡打字面上的 `%`**：要寫成 `\%`，否則會被展開成檔名

## 11. 維護

### 檔案在哪

```
~/.config/nvim/               ← 真身（可以整份丟進 git，全是純文字）
├── init.lua                  ← 入口，設 leader、載入下面四塊
├── TUTORIAL.md               ← 這份文件
├── nvim-pack-lock.json       ← 每個外掛鎖在哪個 commit（自動生成，別手改）
└── lua/
    ├── options.lua           ← 基本選項
    ├── autocmds.lua          ← .ps1 的 BOM、複製高亮、lua 縮排
    ├── keymaps.lua           ← 上面那 5 個鍵，全部在這裡
    ├── plugins.lua           ← 載入器：掃描下面的資料夾並安裝
    └── plugins/
        ├── colorscheme.lua   ← tokyonight
        ├── fzf-lua.lua       ← \f \g \b
        ├── gitsigns.lua      ← ]c [c 與左欄標示
        └── yazi.lua          ← \y \Y（含它的依賴 plenary）

%LOCALAPPDATA%\nvim           ← 目錄 junction，指向上面那個目錄
%LOCALAPPDATA%\nvim-data\     ← 外掛程式碼、undo 歷史、shada。拋棄式，刪了會自己長回來
```

### 更新外掛

```vim
:lua vim.pack.update()
```

會開一個分頁列出每個外掛的變更內容。看過覺得可以就 `:w` 套用，不想要就 `:q` 丟掉。
**不執行這個指令，外掛就永遠停在現在的版本**，不會有「某天自己壞掉」這種事。

### 加一個外掛

在 `lua/plugins/` 底下新增一個 `.lua` 檔，內容照現有的檔案抄：

```lua
return {
  plugin = { src = 'https://github.com/作者/外掛名' },
  config = function()
    require('外掛名').setup({})
  end,
}
```

重開 nvim 就會自動安裝，不必去改任何清單。

### 砍一個外掛

刪掉 `lua/plugins/` 裡那個檔案，然後 `:lua vim.pack.del({ '外掛名' })` 把磁碟上的也清掉。

### 壞掉的時候

| 症狀 | 做法 |
|---|---|
| 開啟時跳警告，但還能用 | 那是 `plugins.lua` 的 `pcall` 擋下來的，訊息會直接寫是哪個檔案出事 |
| 完全開不起來 | `nvim --clean` 一定開得起來（完全不讀設定），先用它把設定檔改回來 |
| 想知道環境有沒有問題 | `:checkhealth`（只看某一項：`:checkhealth yazi`） |

## 12. 第一週練什麼

不要一次全記。照這個順序，每項練到不用想為止再往下：

1. **`Esc` / `:w` / `:q!`** —— 能安全進出，就不會有壓力
2. **`i` `a` `o` 進 Insert，`Esc` 出來** —— 建立「模式」的感覺
3. **`hjkl` 移動** —— 兩三天就會自然
4. **`dd` `yy` `p` `u`** —— 刪除、複製、貼上、復原
5. **`ciw` 跟 `.`** —— 這兩個一旦順了，你會開始感覺到 vim 為什麼值得
6. **`\f` 找檔案、`\g` 搜尋** —— 開始把它當工作環境用

內建還有一份官方的互動教學，大約 30 分鐘，直接在 nvim 裡邊做邊學：

```vim
:Tutor
```

查任何東西都用 `:help`，例如 `:help ciw`、`:help vim.pack`、`:help 'undofile'`。
`:help` 裡按 `Ctrl+]` 進入連結、`Ctrl+O` 返回。
